# CLAUDE.md

Правила совместной разработки для проекта **StolikQR**.

## 1. Язык общения

- Всегда отвечай пользователю на русском языке.
- Код, команды терминала, названия файлов, API, библиотеки и технические идентификаторы — оставляй на языке оригинала (обычно английском), не переводи их.
- Пользователь — начинающий разработчик, осваивает AI-assisted development / vibe coding. Важные технические решения объясняй понятным языком, без лишнего жаргона, коротко раскрывая смысл терминов при первом использовании.

## 2. Режим работы

- Перед существенными изменениями сначала объясни, что собираешься сделать и зачем — не начинай сразу править код.
- Не выполняй destructive-операции без явного подтверждения пользователя.
- Не используй `git reset --hard`, `git clean -fd`, force push и другие потенциально опасные команды без явного разрешения.
- Не удаляй существующий функционал без объяснения причины и согласия пользователя.
- Не меняй архитектуру проекта без предварительного обсуждения.

## 3. О проекте StolikQR

- Это multi-tenant SaaS-платформа для ресторанов.
- Основные направления: guest experience, QR-меню, интерактивные карточки блюд, заказ, электронный официант, бронирование, отзывы, аналитика, waiter/kitchen/admin workflows, в дальнейшем — интеграция с платежами и POS.
- Текущий статус: MVP интерактивного QR-меню на локальных mock-данных (`src/data`), без БД, авторизации, оплаты и внешних API (см. README.md).
- Архитектура должна оставаться расширяемой — учитывай, что позже добавятся реальный backend, авторизация, платежи, роли (гость/официант/кухня/админ).
- Не добавляй функциональность "для демонстрации" — каждое изменение должно соответствовать продуктовой цели.

## 4. Технологии и структура

Стек проекта (см. `package.json`): **Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4**, ESLint (flat config).

Ключевая структура `src/`:
- `app/` — маршруты App Router, в т.ч. `r/[slug]` (страница ресторана), `r/[slug]/t/[tableCode]` (стол/сессия).
- `components/` — UI по доменам: `cart/`, `menu/`, `table/`, `restaurant/`, `layout/`.
- `data/` — mock-данные (рестораны, категории, блюда).
- `cart/`, `table/` — стейт-провайдеры и стор-логика (корзина, сессия стола, заказ, вызов официанта).
- `i18n/` — локализация (провайдер, переводы, типы).
- `lib/` — вспомогательные утилиты.
- `types/` — общие TypeScript-типы.

Правила:
- Всегда сначала смотри `package.json`, прежде чем предполагать, какие библиотеки доступны.
- Не заменяй библиотеку или технологию без необходимости.
- Перед добавлением новой зависимости — объясни, зачем она нужна.
- Предпочитай простые и поддерживаемые решения premature optimization и избыточным абстракциям.
- Следуй существующим соглашениям проекта (структура папок по доменам, паттерны провайдеров/стора, alias `@/*` → `src/*`).

## 5. Git

- Перед изменениями проверяй `git status`.
- Не создавай коммит без явного указания пользователя.
- Перед коммитом сначала покажи, какие файлы изменены и что именно изменилось (`git status` / `git diff`).
- Не изменяй историю Git (rebase, amend, force push и т.п.) без разрешения пользователя.

## 6. Проверка после изменений

После изменений в коде:
- запускай необходимые проверки (`npm run lint`, `npx tsc --noEmit` для типов, `npm run build` при необходимости);
- если изменение касается UI — проверяй результат в браузере (`npm run dev`);
- если обнаружены проблемы — сообщай о них прямо, а не скрывай и не замалчивай.

## 7. Важное правило

Не предполагай, что существующий код неправильный только потому, что можно сделать иначе. Сначала разбирайся в текущей архитектуре и существующих решениях, и только потом предлагай изменения.
